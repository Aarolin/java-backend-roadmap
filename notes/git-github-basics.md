# Git and GitHub basics

## Core terms

- Git: Локальная система контроля версий.
- GitHub: Веб-сервис для хранения git репозиториев.
- Repository: Каталог, история которого контролируется git'ом.
- Working tree: Файлы репозитория.
- Staging area: Промежуточная область, куда Git помещает выбранные версии файлов перед созданием следующего commit.
- Commit: Снимок изменений файлов из staging area. В нем находится принятое состояние файла.
- Branch: Подвижный указатель на commit. Через этот commit Git видит цепочку предыдущих commit'ов, то есть историю ветки.
- Remote: Ссылка на удаленную копию репозитория.
- Origin: Короткое имя для ссылки на удаленный репозиторий.
- Push: Команда отправляет коммиты в удаленный репозиторий.
- Clone: Копирует удаленный репозиторий вместе с историей коммитов и ветками.
- SSH: 
- Public key: публичный ключ, который можно добавить в GitHub. Он не является секретом.
- Private key: приватный ключ, который хранится только на моём компьютере. Его нельзя отправлять в GitHub, архивы, чаты или мессенджеры.
- GitHub проверяет, что мой компьютер владеет приватным ключом, соответствующим публичному ключу в настройках аккаунта.

## Change flow

```text
Working tree
    -> git add
Staging area
    -> git commit
Local repository
    -> git push
GitHub repository
```

## Глобальные настройки
| Command                                       | Meaning |
| --------------------------------------------- | ------- |
| `git config --global user.name "..."`         | Установить имя пользователя в настройки. В сделанных изменениях будет отображаться это имя. |
| `git config --global user.email "..."`        | Установить email для пользователя в настройки. |
| `git config --global init.defaultBranch main` | Установить имя main для ветки по умолчанию. |
| `git config --global core.autocrlf true`      | Настраивает обработку окончаний строк CRLF/LF на Windows. Помогает хранить текстовые файлы в репозитории в нормализованном виде и уменьшает проблемы при работе между Windows, Linux и macOS. |


## Ежедневные команды
| Command               | Meaning |
| --------------------- | ------- |
| `git status`          | Показывает текущее состояние рабочей области и области индексации (staging area).        |
| `git add <path>`      | Добавляет файлы по пути path в область индексации (staging area).        |
| `git diff`            | Показывает изменения, которые ещё не добавлены в staging area.        |
| `git diff --cached`   | Показывает изменения, которые будут добавлены в следующий коммит.        |
| `git commit -m "..."` | Фиксирует изменения. -m прикрепляет сообщение к изменениям.        |
| `git log --oneline`   | Показывает историю изменений в текущей ветке. --oneline помогает вывести историю построчно.       |
| `git switch <branch>` | Переключиться на другую ветку.         |
| `git push`            | Отправить изменения в удаленный репозиторий.        |
| `git pull`            | Получить изменения из удаленного репозитория.        |
| `git clone <url>`     | Скопировать репозиторий на свой компьютер.        |

## Мои объяснения
1. Разница между git add и git commit: команда git add добавляет текущее состояние указанных файлов в область подготовленных изменений.
Команда git commit это как подтверждение нужных нам изменений, которые мы до этого добавляли в область.
2. Разница между commit и push: commit фиксирует изменения локально на компьютере. Push отправляет изменений в удаленный репозиторий.
3. Разница между Git и Github: Git - система контроля версий, которая позволяет отслеживать изменения файлов и быстро возвращаться к нужным версиям при необходимости.
Github - интернет-сервис для хранения Git репозиториев.
4. Разница между различными ветками (например main и feature): ветка - это отдельная последовательность commit'ов (принятых изменений). Разные ветки помогают разделить
изменения, которые должны попасть в рабочую версию репозитория, и предположим, в тестовую.
